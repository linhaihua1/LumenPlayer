# LumenPlayer 产品需求规格说明书（PRD）

| 项目 | 内容 |
|------|------|
| 产品名称 | LumenPlayer（流明播放器） |
| 版本 | v1.0（需求基线，未开发） |
| 日期 | 2026-11-20 |
| 平台 | 一期 Windows 10/11 x64 → 二期 Android → 三期 HarmonyOS NEXT |
| 定位 | 面向 480p/720p 老片源的「实时 AI 画质增强」本地播放器 |

---

## 1. 产品定位与边界

### 1.1 一句话定位
**按下播放键，九十年代的老片当场变干净、变锐利、变通透；不用学参数，不用等渲染。**

### 1.2 三层价值主张

| 层 | 主张 | 竞品差异 |
|----|------|----------|
| 快 | 实时增强，零等待 | Video2X / Topaz 是"处理几小时出文件"，不是播放器 |
| 懂 | 针对 90—00 年代片源缺陷（隔行/胶转磁/块效应/色域错标）自动处理 | 通用超分模型直接怼隔行帧会放大梳齿 |
| 真 | A/B 对比 + 性能 HUD，效果与代价都看得见 | 多数工具是黑盒，用户不知道有没有生效 |

### 1.3 明确不做（一期范围红线）

| 不做 | 原因 |
|------|------|
| 不提供、不索引、不搜索、不下载任何影视资源 | 版权合规红线 |
| 不做 DRM 解密 / 不处理加密流 | 合规红线 |
| 不做 HDR 真映射 / 不做 4K 输出 | 一期算力与收益不匹配 |
| 不做云同步、账号体系、社交分享 | 范围裁剪，一期纯本地 |
| 不做直播/流媒体协议（HLS/DASH 在线流） | 二期评估 |
| 不修改用户原文件（除显式导出） | 数据安全底线 |

## 2. 用户与场景

### 2.1 目标用户

| 画像 | 特征 | 核心诉求 | 占比预估 |
|------|------|----------|----------|
| 怀旧剧迷 | 手里有大量 DVD 转录/下载的老剧，用 1080p 显示器看糊得难受 | 打开就能看清，别让我调参数 | 55% |
| 影迷收藏党 | 在意胶片颗粒、色准、画幅，反感"AI 塑料感" | 可控、可对比、能导出收藏 | 25% |
| 低配用户 | 核显笔记本/老台式 | 别卡、别崩、别装不上 | 20% |

### 2.2 典型场景（用户故事）

1. 作为怀旧剧迷，我把《XX》DVD 转录的 480p MKV 拖进播放器，它自动识别是隔行 NTSC 片源，去隔行后超分到 1080p，我看到的是干净的画面，全程没点过任何设置。
2. 作为影迷，我觉得默认档皮肤有点"塑料"，按住对比键看原片，把颗粒保留从 60 调到 85，画面质感回来了。
3. 作为低配用户，我的核显跑不动 AI 模型，播放器提示"已切换到轻量增强模式"，画面仍然比原来锐利，且不卡。
4. 作为收藏党，我把 20 集老剧加入导出队列，晚上挂着跑，第二天得到 20 个 1080p 文件。
5. 作为怀疑派，我打开 HUD 看到"后端：DirectML / 模型：xxx / 18.4ms/帧 / 丢帧 0"，我确认它真的在工作。

## 3. 功能需求清单

> 优先级：**P0** = 一期上线门禁；**P1** = 一期可选，资源够就做；**P2** = 二期/三期。

### 3.1 播放核心（P0）

| ID | 功能 | 说明 | 验收标准 |
|----|------|------|----------|
| F-101 | 打开媒体 | 拖拽/双击/文件对话框/最近列表/命令行 | 支持 MKV/MP4/AVI/WMV/RMVB/TS/M2TS/FLV/WEBM/ISO(部分) |
| F-102 | 播放控制 | 播放/暂停/停止/逐帧/倍速 0.5–2.0/音量/静音 | 全部支持快捷键，状态与 UI 同步 |
| F-103 | 进度与跳转 | 拖动、快进快退 5/10/30s、章节跳转 | seek 后画面正确，无花屏，音画不脱节 |
| F-104 | 音轨 | 多音轨切换、声道选择、直通输出 | 切换即时生效，不中断播放 |
| F-105 | 字幕 | 内嵌/外挂 SRT/ASS/SUP，延时、字号、位置、描边 | 调整实时生效并持久化 |
| F-106 | 播放列表 | 拖入多文件、顺序/循环/随机、记住进度 | 多文件进度不串 |
| F-107 | 显示适配 | 全屏/窗口/无边框、比例锁定、多显示器、刷新率自适应 | 拖到不同刷新率屏幕不产生新抖动 |
| F-108 | 记忆与恢复 | 每片进度、音量、档位、自检结果持久化 | 崩溃/重启后可恢复 |

### 3.2 片源自检（P0 — 差异化核心）

| ID | 功能 | 说明 | 验收标准 |
|----|------|------|----------|
| F-201 | 隔行/逐行检测 | 逐帧场分析，判定是否隔行、是否 3:2 pulldown | 标准样本集判定准确率 ≥90% |
| F-202 | IVTC / 去隔行 | 胶转磁片源还原 23.976；纯视频隔行走运动自适应去隔行 | 输出无梳齿、无场序错乱 |
| F-203 | 分辨率与像素比 | 识别 SAR/DAR，处理变形宽银幕 | 画面不变形、不出现黑边套黑边 |
| F-204 | 黑边检测与裁切 | 检测 letterbox/pillarbox | 黑边不被放大；可选自动裁切 |
| F-205 | 色域与色彩范围 | BT.601/709 识别，TV/PC range 纠正 | SD 片源肤色正确，无偏绿偏红 |
| F-206 | 颗粒/噪点/块效应评估 | 量化噪声与压缩损伤等级 | 输出 `DamageProfile` 用于选链 |
| F-207 | 内容类型判定 | 实景 / 动画 / 混合 | 动画片源正确切换动画链（准确率 ≥85%） |
| F-208 | 决策与明示 | 生成处理链并显示在 HUD | 用户可查"为什么这样处理" |

### 3.3 实时超分增强（P0）

| ID | 功能 | 说明 | 验收标准 |
|----|------|------|----------|
| F-301 | 实时超分 | 480p/576p/720p → 1080p | 24/30fps 片源稳态零丢帧 |
| F-302 | 三档预设 | 性能 / 均衡 / 画质，可热切换 | 切换无黑屏无卡顿，HUD 同步 |
| F-303 | 自动选档 | 按硬件能力 + 片源损伤自动选档 | 首次启动即给出合理默认，无需用户配置 |
| F-304 | 手动覆盖 | 用户可锁定档位/关闭增强 | 用户意愿优先于自动策略 |
| F-305 | A/B 对比 | 左右分屏、上下分屏、按住看原片 | 即时生效，两画面严格同帧 |
| F-306 | 截图对比 | 一键导出同帧前后对比图 | 文件名含时间码与参数 |
| F-307 | 颗粒保留 | 0–100 可调，默认偏保守（60–80） | 默认档颗粒能量保留 60%—80% |
| F-308 | 降级链 | AI 不可用 → shader 上采样 → 传统插值+锐化 | 任何硬件都能播，不出现"打不开" |
| F-309 | 预热与构建 | 模型预热、engine 构建带进度 | 首次播放不表现为卡死 |

### 3.4 性能可观测（P0）

## 4. 非功能需求

| 类别 | 指标 | 门禁 |
|------|------|------|
| 性能 | 1080p 输出稳态零丢帧、掉帧率 <0.5%/10min、首帧 ≤1.5s、启动 ≤3s | 上线门禁 |
| 资源 | 常驻内存 <1.5GB、3h+200 次 seek 泄漏 <100MB、GPU 余量 ≥20% | 上线门禁 |
| 同步 | 音画漂移 <40ms（3h 累计） | 上线门禁 |
| 稳定性 | 畸形文件 fuzz 0 崩溃；TDR 后自愈；连续 10h 播放不崩 | 上线门禁 |
| 兼容性 | Win10 21H2+ / Win11；NVIDIA GTX10xx+、AMD RX5000+、Intel UHD630+/Arc | 硬件矩阵抽测 |
| 可用性 | 新用户首次打开文件到看到增强画面 ≤3 次操作 | 可用性测试 |
| 合规 | 无 AGPL 依赖、无 GPL 编码器、无网络请求、不写源目录 | 法务+安全审计 |
| 可维护性 | HUD + 诊断包 + 结构化日志（含原因码） | 上线门禁 |

## 5. 硬件分级与档位映射（建议基线）

| 档位 | 目标硬件 | 模型量级 | 单帧预算 | 策略 |
|------|----------|----------|----------|------|
| 画质 | RTX 4070+ / RX 7800+ | 中等 Real-ESRGAN 变体 / 大 Compact | ≤28ms | 2x 超分 + 轻去块 + 颗粒保留 |
| 均衡（默认） | RTX 3060 / RX 6600 / Arc A750 | Compact | ≤28ms | 2x 超分 + 可选前置去隔行 |
| 性能 | GTX 1650 / 核显 Iris Xe / Vega | UltraCompact 或 shader | ≤20ms | shader 超分（Anime4K 类算法）+ 锐化 |
| 兼容 | 无可用 GPU / 老驱动 | 无模型 | — | 传统 Lanczos/FSR 类 + CAS 锐化 |
| 旁路 | 源已 ≥1080p | — | — | 不增强，仅正确色彩与缩放 |

> ⚠️ 上表为**待 POC 校准的假设值**，M0 阶段用真实老片片段在目标卡上实测后回填。

## 6. 关键流程（文字版）

**首次启动**：硬件自检 → 跑分与档位推荐 → 模型下载/解压（带进度）→ 预热 → 可交互

**打开文件**：解析容器 → 解封装 → 自检（≤800ms）→ 生成 SourceProfile + 处理链 → 首帧渲染 → 播放

**播放中**：解码 → 预处理（去隔行/裁切/色域）→ 推理超分 → 后处理（颗粒/锐化/抖动）→ 呈现；同时运行帧节奏监控，超预算则降档

**降级**：监控发现连续 N 帧超预算 → 切低档模型 → 仍不达标则切 shader → 仍不达标则提示"建议关闭增强"（不自动关）

## 7. 开放问题（需产品/用户决策）

| # | 问题 | 建议 |
|---|------|------|
| 1 | 实时 vs 离线，一期是否都要？ | 建议 P0 只做实时，导出放 P1 |
| 2 | 模型是否随包分发（安装包体积）？ | 建议基础档随包（~30—80MB），高档按需下载 |
| 3 | 是否需要"一键模仿蓝光调色"（对比度/饱和度预设）？ | 建议不做，容易变成"滤镜"，与"保真"定位冲突 |
| 4 | 是否支持 4:3 老片自动裁黑边+拉伸到 16:9？ | 建议默认不裁（破坏构图），仅提供可选 |
| 5 | 收费模式？ | 未定，影响是否可闭源及依赖许可选择 |
