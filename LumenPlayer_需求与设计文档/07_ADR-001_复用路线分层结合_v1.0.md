---

## 1. 背景

06 文档给出三条互斥路线（A 开源复用 / B 自研外壳+复用引擎 / C 全自研），前提假设是"整条产品线只选一条"。

这个前提是错的。A/B/C 本质上是**三层不同东西的来源策略**：

- **A 是基建**（播放内核：解封装、解码、字幕、同步、seek）
- **B 是引擎**（推理层：后端适配、零拷贝、设备丢失自愈）
- **C 是产品**（策略层：片源自检、场处理、色域、颗粒、降级决策）

这三层的许可、生命周期、复用价值完全不同，**没有理由用同一把尺子量**。

---

## 2. 决策

**采用分层结合：A 做地基、C 做核心、B 做可替换件。三条路线同时存在于一个产品里，但各自待在自己的层。**

| 层 | 取哪条 | 具体来源 | 为什么 | 许可归属 |
|----|--------|----------|--------|----------|
| **基建层**<br>播放内核 | **A** | 一期 fork 上游 `mpv-player/mpv`；将来闭源则换 **LGPL 构建的 libmpv + 自渲染** | 字幕/同步/seek/格式这四件事重写毫无产品价值；上游二十年积累 | 一期 GPLv2+（自用/开源不分发则不触发）；二期 LGPLv2.1 |
| **引擎层**<br>推理后端 | **B** | 一期接 `libaji` 二进制（研究/自用）；二期三选一：谈授权 / 自研 ORT-DirectML 后端 / 换 NCNN | 免写 D3D11↔CUDA 互操作；但必须**可替换**，不能被它锁死 | 一期无许可（仅自用）；二期自有或已授权 |
| **产品层**<br>策略与体验 | **C** | **100% 自研** | 上游全是"动漫+1080p→4K"，老片这套没人做；这是唯一的产品护城河 | 完全自有，可闭源 |

**一句话**：**A 是脚手架，B 是期货，C 是房子。** 只有 C 必须马上开工，A 用来省时间，B 等有结论再定。

---

## 3. 关键机制：三道接缝（Seam Contract）

分层的价值全在接缝上。接缝定错，将来换任何一层都是重写。**接缝一旦定版即冻结，业务层不得 include 任何 mpv / libaji 头文件。**

### 接缝 1 — 帧契约（含零拷贝要求）

```
FrameDesc {
  w, h
  pixel_format        // NV12 / P010 / RGB10A2，闭集
  stride[3]
  gpu_texture         // D3D11 纹理或 DXGI 共享句柄；不得暴露内存指针
  pts_us              // 微秒；超分后必须原样透传，不许重算
  color               // primaries + matrix + range（601/709，limited/full）
  sar                 // 像素宽高比，未归一化前不许缩放
  is_interlaced       // 场处理前的原始标记，供策略层决策
}
```

**硬约束**：全链路 GPU 常驻。任何一次 1080p 回读 CPU = 数 ms + 带宽灾难（04 §5.3）。

### 接缝 2 — 引擎契约

```
class ISRBackend {
  bool Init(const ModelSpec&, const DevicePref&);
  bool Warmup(IProgress*);                       // 异步，首次可能分钟级
  bool Infer(const FrameDesc& in, FrameDesc& out);
  PerfStats Stats() const;                       // ms/帧、显存
  void OnDeviceLost();                           // TDR 自愈
}
// 错误码闭集；禁止异常跨越边界；禁止在业务层判断"是不是 TensorRT"
```

**硬约束**：业务层只知道 `ISRBackend`，不知道 libaji、不知道 DirectML。二期换后端时**上层零改动**。

### 接缝 3 — 策略契约

```
ProcessingChain {
  stages: [ Deinterlace | IVTC | Crop | ColorFix | Deblock | Denoise | SR | GrainReinject | Sharpen ]
  params: { strength, model_id, target_res, budget_ms }
}
```
序列化后交给引擎与 UI，UI 只读展示（HUD 用），不得回写。

## 4. 许可如何共存：用进程边界，不是用重写

若将来要闭源分发，GPL 的 mpv 与闭源 UI 不能链接在同一个可执行文件里。解决办法是**进程隔离**——FSF 认可的判定标准是"独立进程 + 通用 IPC 通信通常不构成衍生作品"：

```
lumen-ui.exe   (自有许可，闭源)      ← 策略层 / UI / 设置 / 导出队列
      │  named pipe：控制指令 + 状态
      │  DXGI 共享纹理句柄：帧（零拷贝，不复制像素）
lumen-core.exe (GPLv2+，可开源)      ← mpv fork（或 libmpv 宿主）+ 解码/渲染
```

**代价**：跨进程共享 GPU 纹理约 0.5—1ms/帧，且需要处理对端崩溃与句柄生命周期。**一期先做单进程（GPL 阶段不需隔离），接缝 1 已按"可跨进程"设计，二期切换不返工。**

> 若最终确定**完全开源** → 永远不需要这一节，单进程即可，省 1—2 周。

## 5. 落地顺序（结合后不改变起点）

| 阶段 | 内容 | 层 | 为什么这个顺序 |
|------|------|----|----------------|
| W1 | mpv-AnimeJaNai release + `aji_harness` 跑基准，只评估不写码 | — | 先买确定性，零法律风险 |
| W2—W3 | fork 上游 mpv + 滤镜骨架跑通 | A | 先把"能播能超分"立起来 |
| W3—W6 | **策略层全量**：自检、IVTC、601→709、4:3、颗粒回注、A/B | **C** | 唯一必须做的，也是唯一带得走的 |
| W5—W7 | `ISRBackend` 抽象 + libaji 接入 | B | 与策略层并行，不阻塞 |
| **W8** | **决策门**：性能达标？要卖钱？ | — | 决定 A 是否降级为 LGPL、B 是否换自研 |

**结合不等于同时开工。顺序仍是：W1 评估 → A 铺路 → C 主攻 → B 补位。**

## 6. 结合带来的新增风险

| # | 风险 | 应对 |
|---|------|------|
| N1 | **接缝过度设计**：为了"将来可换"把接口抽象得太复杂，solo 开发卡死在架构上 | 接缝只做三个（帧/引擎/策略），每个 ≤5 个方法；不做插件系统、不做动态注册表 |
| N2 | **过早抽象**：还不知道 libaji 怎么用就定接口，接口必然错 | W2—W3 先用**硬编码调用**跑通，W5 再抽 `ISRBackend`（有第二个实现时再抽象，这是rule of three 的务实版） |
| N3 | **接口泄漏**：某个业务函数里顺手 `#include "aji.h"`，二期全炸 | CI 加一条静态检查：业务层目录禁止出现 mpv/aji/onnxruntime 头文件 |
| N4 | **进程隔离的调试成本**：崩了不知道是谁崩的 | 接缝 1 就带 `trace_id`，两端日志同一 id 可串 |
| N5 | **三套节奏**：A 层跟上游走、B 层跟作者走、C 层跟自己走，上游 breaking change 打乱计划 | 锁定上游 commit（pin），只在里程碑之间升级 |

---

## 7. 明确不做（防止"结合"变成"全都想要"）

- ❌ 不做插件市场 / 动态加载第三方滤镜
- ❌ 不为了兼容 B 的两种后端而写两套渲染路径
- ❌ 不在 C 层之外复制一份"策略"给离线导出用（导出必须复用同一策略层，否则两套画质不一致）
- ❌ 不追求"三平台共用一套 UI"

---

## 8. 后果

**收益**
- 拿到 mpv 的全部基建（省 3—6 个月），同时把研发时间全部投在唯一有差异化的策略层
- 将来无论"开源 / 闭源 / 卖钱 / 自用"，**策略层与 UI 都能整段带走**，只有引擎层和内核层需要适配
- B 层保持"可换"，避免被一个无许可的第三方库锁死

**代价**
- 多付 1—2 周做接缝（W5 才付，前期不阻塞）
- 若最终闭源，多付 1—2 周做进程隔离

**判定为成功的标准**
在 W8 决策门，能做到：仅替换 `ISRBackend` 实现（libaji → 自研），**策略层与 UI 零改动**，画质与性能不退化。
